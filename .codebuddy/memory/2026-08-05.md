## 修复：iOS 模拟器编译失败 "PhaseScriptExecution failed / aot_assembly_release"

**真正的根因**（最终从完整构建日志确认）：Xcode Run scheme 在**模拟器**上用 **Release** 配置构建，触发 Flutter 的
`Target aot_assembly_release failed: release/profile builds are only supported for physical devices. attempted to build for simulator.`
日志特征：`CONFIGURATION=Release` + `EFFECTIVE_PLATFORM_NAME=-iphonesimulator` + `Runner.xcodeproj/project.pbxproj` 里 `defaultConfigurationName = Release`。

**坑点**：之前只改 `LaunchAction buildConfiguration="Debug"` 不够。Xcode 开着时会还原文件；且 `BuildAction` 缺显式 `buildConfiguration` 时，
Runner 及其 Pods 依赖会 fallback 到项目默认 `defaultConfigurationName = Release`，所以 Run Script 阶段仍用 Release。

**最终修复**（已落盘，需在 Xcode 完全退出后改文件否则被还原）：
`ios/Runner.xcodeproj/xcshareddata/xcschemes/Runner.xcscheme` 的 `<BuildAction>` 加 `buildConfiguration = "Debug"`。
同时删除 `ios/Pods/Pods.xcodeproj/xcuserdata/*/xcschemes/` 下 CocoaPods 自动生成的个人 pod scheme（避免误用）。
`LaunchAction`/`TestAction` 已是 Debug；`ProfileAction`=Profile、`ArchiveAction`=Release（真机归档保持 Release 正确）。

**操作要点**：
- 必须完全退出 Xcode（⌘Q，必要时 `kill -9` PID）后再改 scheme 文件，否则被还原。
- 重开务必带 locale：`LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 open ios/Runner.xcworkspace`（防 CocoaPods 编码崩溃）。
- 模拟器 ⌘R 用 Debug；真机 Archive 用 Release，二者不冲突。
- 若仍失败，可直接命令行绕过 GUI：`flutter run -d "iPhone 16" --debug`。

**经验**：排查 iOS 构建问题要抓完整环境变量日志里的 `CONFIGURATION` 和 `EFFECTIVE_PLATFORM_NAME`，比 GUI 报错准。

## 修复：真机 IAP "商品加载失败"

**根因**：`Runner.xcscheme` 的 `<LaunchAction>`（Run action）里挂了
`<StoreKitConfigurationFileReference identifier = "../../warring_states_card/ios/Runner/Configuration.storekit">`。
这是本地模拟器调试用的静态 StoreKit 文件，且相对路径指向了 `warring_states_card` 子项目，在真机 Run 时加载失败，
导致真机 StoreKit `queryProductDetails` 返回 0 个商品 → `ensureReady()` 返回 false → "IAP 商品加载失败"。

**修复**：删除 `LaunchAction` 里的 `StoreKitConfigurationFileReference` 整段，真机走真实沙盒环境。
（同样需在 Xcode 完全退出后改文件，否则被还原。）

**关键区分（重要，纠正此前误区）**：
- 模拟器调试 → 可挂 `Configuration.storekit` 本地文件（无需沙盒账号即可读到 gem_* 商品）。
- 真机沙盒测试 → **绝不能**挂本地 StoreKit 文件，必须设为 None，且真机必须登录 **App Store Connect 的 Sandbox Tester**
  （在 App Store Connect → Users and Access → Sandbox Testers 创建，不是 Xcode 本地配置）。
- **两种"沙盒"不同**：设置→开发者 里的「本地 StoreKit 配置」是 Xcode 本地调试用，真机购买无效；
  真正的沙盒测试员登录入口是 设置→App Store→沙盒账户(iOS17+) 或 设置→Apple ID→媒体与购买项目(iOS16-)。
- 用户设备"设置里没有 App Store"且沙盒在"设置→开发者"下 → 说明其登录的是 Xcode 本地 StoreKit 会话而非 App Store Connect 沙盒测试员，
  这导致 `storekit_no_response` / `queryProductDetails got 0/5`。需先建真实 Sandbox Tester 并登录真机。
- gem_* 5 个 IAP 当前状态 Waiting for Review，沙盒可正常购买；App Store Connect Product ID 必须区分大小写等于
  `gem_60/gem_300/gem_600/gem_1500/gem_3000`；所属 App Bundle ID 必须 = `com.game.Warringstates`。
- `battle_pass_premium` / `starter_bundle` 两个 purchase() 调用在 App Store Connect 无对应商品，必然失败（与本次 gem 无关，另议）。

## 修复：`audioplayers_darwin` module not found（反复出现）

**根因**：`ios/Runner.xcworkspace/contents.xcworkspacedata` 里有一个**错误的 FileRef**：
```xml
<FileRef location = "group:../warring_states_card/ios/Runner/Configuration.storekit"></FileRef>
```
这个相对路径指向不存在的 `warring_states_card` 子项目（历史残留），Xcode 加载 workspace 时解析它出错，干扰了整个 Pods 子工程的加载/构建顺序。
同时 DerivedData 缓存了旧的中间产物，导致 `__has_include(<audioplayers_darwin/...>)` 预处理时 framework 还没构建出来 → 走 `@import` → 模块也找不到 → "module not found"。

**修复步骤（必须按顺序，且 Xcode 完全退出）**：
1. `pod deintegrate`（移除主工程里所有 Pods 引用，恢复干净状态）
2. `pod install`（重新集成，会重新生成 xcconfig baseConfigurationReference）
3. 删除 `contents.xcworkspacedata` 里指向错误路径的 `Configuration.storekit` FileRef
4. `rm -rf ~/Library/Developer/Xcode/DerivedData/*`（全清 DerivedData）
5. 重开 Xcode，等索引完成，⌘R

**关键认知**：
- Flutter iOS 工程的 Pods 子工程通过 **workspace**（`Runner.xcworkspace`）引用 `Pods/Pods.xcodeproj`，不在主 `Runner.xcodeproj/project.pbxproj` 里加 PBXFileReference。
  所以 `grep "Pods.xcodeproj" Runner.xcodeproj/project.pbxproj` 无匹配是**正常**的，不是根因。
- `pod install` 不会向主 pbxproj 注入 Pods.xcodeproj 引用；它只生成 `Pods.xcodeproj` 和 xcconfig。
- `GeneratedPluginRegistrant.m` 的 `#if __has_include` 在 framework 未构建时会失败 → `@import` 兜底也失败 → 报错。
  首次构建必须保证 DerivedData 干净、workspace 引用正确，让 Pods 先编译。
- workspace 里任何指向不存在路径的 FileRef 都会干扰 Xcode 加载，必须删除。

## 修复：`audioplayers_darwin` module not found（真正根因）

**根因**：`ios/Runner.xcodeproj/project.pbxproj` 里 Runner target 的 build settings 有
`SUPPORTED_PLATFORMS = iphoneos`（**只支持真机，不支持模拟器**）——有两处（Debug 配置第 471 行、Release 配置第 653 行）。
这导致模拟器构建时 Pods framework 路径/架构解析错误，`__has_include` 找不到头 → `@import` 也失败 → "module not found"。
同时 `xcodebuild -showdestinations` 虽列出模拟器，但实际构建时 Runner scheme 的可用 destination 只有 My Mac/真机/Any iOS Device（无模拟器）——这是 Xcode 的 SHOW vs BUILD 行为差异。

**修复**：把两处 `SUPPORTED_PLATFORMS = iphoneos` 改成 `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator"`。
命令行验证：`xcodebuild -workspace Runner.xcworkspace -scheme Runner -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 15 Pro Max' CODE_SIGNING_ALLOWED=NO build` → BUILD SUCCEEDED。

**教训**：
- `module not found` 反复出现且 pod 本身能单独构建成功时，先查 `SUPPORTED_PLATFORMS` 是否包含 `iphonesimulator`。
- `xcodebuild -showdestinations` 显示的 destination 不等于实际可构建的 destination，以真实 build 报错为准。
- Flutter iOS 工程标准配置是 `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator"`，只有 `iphoneos` 是异常的（可能被某个工具或手动改动改过）。

## 修复：PhaseScriptExecution failed (release/profile builds not supported for simulator)

**根因**：Xcode GUI 里 Runner scheme 的 Run configuration 被设成了 **Release**，但 **Flutter 的 Release/Profile 用 AOT 编译，AOT 不支持模拟器**（只支持真机）。
报错：`Target aot_assembly_release failed: Exception: release/profile builds are only supported for physical devices. attempted to build for simulator.`
命令行 `xcodebuild -configuration Debug` 能过，但 GUI 用 Release 跑模拟器必失败。

**修复**：Runner scheme → Edit Scheme → Run → **Info** → Build Configuration 改回 **Debug**。
或直接 `flutter run -d <simulator_id> --debug`（默认 Debug，绕开 Xcode GUI 配置）。

**关键认知**：
- 模拟器只能跑 Debug（JIT）。Release/Profile（AOT）只能真机。
- `flutter run` 默认 Debug；Xcode GUI 的 scheme Run configuration 需手动确保是 Debug。
- flutter 看不到关机的模拟器，必须 `xcrun simctl boot <id>` + `open -a Simulator` 启动后 flutter 才能识别。

## IAP 模拟器方案最终状态

- `flutter run --debug` 能让 app 在模拟器跑起来，但 `flutter run` **不注入本地 StoreKit 配置**。
- 模拟器读本地 `Configuration.storekit` 的唯一方式：**Xcode GUI** Edit Scheme → Run → Options → StoreKit Configuration 选该文件。
- 手改 scheme XML 的 `StoreKitConfigurationFileReference` 在 Xcode 26 不生效，必须 GUI 设。
- 设好 StoreKit Configuration 后，Run configuration 必须是 Debug（模拟器不支持 Release AOT）。
